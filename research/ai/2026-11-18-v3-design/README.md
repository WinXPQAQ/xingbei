# V3 决策接口与网络分工

V3 对局中，每个座位的英雄网络给出最终选择。通用网络先给普通选项评分，英雄网络在这个判断上按自身技能、资源和手牌修正。提炼和英雄技能候选由当前英雄的网络单独评分。通用局面编码可以提供双方阵容、士气、星杯、公开资源和当前座位可见的牌面。

V2 全队训练中，贤者的承伤偏好影响了其他英雄的治疗选择。局部搜索的 579 个贤者应对决策中，只有 14 个选项差异达到显著性门槛，方向也不一致。V3 让每个英雄学习自己的承伤和留牌取舍，并把法典、反弹这类组合直接做成候选牌组。

## 候选动作如何路由

| 候选 | 通用网络 | 当前英雄的网络 |
|---|---|---|
| 普通攻击、法术、应战、抵御、普通弃牌、购买、合成 | 先判断 | 读取通用结果，进一步评分 |
| 提炼 | 提供局面表示 | 独立评分 |
| 主动或启动技能、可选触发、技能费用和目标 | 提供局面表示 | 独立评分 |
| 购买前置、爆牌等基础规则下的必选操作 | 对普通候选先判断 | 进一步评分 |
| 自动触发与结算 | 由引擎处理 | 有合法的玩家分支时按请求归类 |

用当前决策座位的实时英雄 ID 找专属网络，角色替换后重新路由。接口要明确区分技能来源、作答座位、候选类别和询问阶段。一个对手技能造成伤害时，受击者的普通治疗仍走通用评分再由受击者英雄修正。技能明示的费用或独有目标由有权作答座位的英雄网络评分。多步骤与嵌套触发在每个实际时点重算合法候选。

混合根节点会同时出现攻击、技能和提炼。首版从 V2 初始化通用评分和独立的英雄参考评分。同一批合法候选上，普通组用通用网络排序，再用冻结参考分的 `logsumexp` 校准该组的总概率质量。贤者在普通组上叠加自己的修正，技能与提炼用专属分。初始修正为零，初始 logits 与 V2 在相同候选上的评分一致。所有合法候选在同一次 softmax 或贪婪比较中参与选择。其他英雄先使用冻结参考分处理专属候选，普通候选使用零修正。

## 技能接口

引擎确定时点、合法性、信息可见性和结算。V3 把能一起决定的材料、数量和目标组装为有明确含义的候选。材料、费用、数量或目标依赖摸牌、揭示或其他座位作答时，按实际时点分段询问。等价实体只在规则效果、可见性和后续合法性都等价时合并。只有存在合法的放弃路线时才提供放弃。

[逐英雄技能接口设计](heroes.md)覆盖研究和主项目注册表中的 72 个英雄。铸律者按角色转换接管决策，魔弓 EX 单列。常规训练阵容使用另外 70 个起手英雄。

## 提炼的英雄分类

提炼由专属网络评分。原有分类可用于设计训练局面和检查项。

| 类型 | 英雄 |
|---|---|
| 几乎无关 | 游击士 |
| 稳定收益 | 战斗法师、血巫、魔剑 |
| 改变对局（多数英雄） | 魔枪、苍炎、红莲、血剑 |
| 没能量时必须提炼，有了就不急 | 贤者、狂战、英灵 |
| 提炼多少用多少，节奏各异 | 剑帝、魔弓 |

## 贤者专属接口（`training/entity/sage-v3.mjs` 原型）

**魔道法典**
- X 只提供 2、最大值，以及"最大值 −1"。最大值 −1 只在能保留光或暗时提供，并且保留的那张是光/暗。
- 其余中间值从程序上排除。
- 确定 X 后，牌的组合基本固定。
  - 同类等价牌由程序选定实体。原型默认优先弃法术牌，保留攻击牌。
  - 同系攻击牌和法术牌体现不同留牌计划时，正式接口保留一个小选择，让英雄网络决定留哪张。
- 只提供自己或敌人作为目标，X=2 时默认选自己。

**圣洁法典**
- X 只提供 4 和 5，6 及以上不提供。仅能凑出 3 种系时提供 X=3。
- 只提供自己或队友作为目标。按引擎规则选 1 到 X−2 名不同角色，目标数组随候选一起验证。

**法术反弹**
- 第一层选项：不反弹。每个系一个最大同系组合。该系超过 2 张时再加一个 2 张组合。
- 选定后只问目标（自己或敌人）。
- 同类同系的牌由程序代选。

**已验证的候选组示例**

| 情况 | 生成的选项 |
|---|---|
| 手牌 风风地水火光，魔道法典 | 5（风地水火光）/ 4（风地水火，留光）/ 2（风地） |
| 同上，圣洁法典 | 5 / 4 |
| 受 1 点法伤，手牌 火火火水，反弹 | 不反弹 / 3 火 / 2 火 |
| 受 1 点法伤，手牌 风风水，反弹 | 不反弹 / 2 风 |

## 实现与训练顺序

1. 使用 `hierarchical-v3` 构建合法候选和普通候选掩码，按实际作答英雄编码。学习席位用 V3，冻结对手仍走 V2。贤者的法典和反弹优先走牌组选项，其他英雄沿用已实现的引擎技能接口。
2. 从 V2 初始化，先冻结编码器与英雄参考评分，使用随机阵容中的三个学习席位训练通用评分器。选中普通候选且有普通选项可比较时才更新通用评分。奖励只取标准规则终局胜负。
3. 从通用阶段的检查点进入贤者阶段，冻结通用评分。只收集贤者席位的决策，更新贤者评分器，技能、提炼及普通动作修正进入同一个 PPO 分布。每阶段的价值头独立更新。早期固定种子用于监控，胜率确认另用从未用于选版的种子。

## 单卡运行

工作目录是 [研究训练源码](../2026-11-15-branch-targets/source)。`V2_CHECKPOINT` 指 V2 特征版第 907 轮检查点，`FROZEN_DIR` 含 `frozen-current.pt` 和 `frozen-417.pt`。先用固定种子比较对局吞吐，再将报告的 `recommended_workers` 传给正式训练。同一个 Python 进程内批量调度 GPU 推理，`--workers` 是同时运行的 Node 对局数。

```sh
export XINGBEI_TORCH_THREADS=2 OMP_NUM_THREADS=2
python training/entity/benchmark-v3.py "$V2_CHECKPOINT" "$FROZEN_DIR" \
  --workers 12 16 18 20 --games 72 --cycles 2 --output worker-sweep.json
python training/entity/run-v3.py "$RUN_DIR" --initial "$V2_CHECKPOINT" \
  --opponents "$FROZEN_DIR" --revision "$SOURCE_REVISION" --workers "$WORKERS" \
  --shared-rounds 8 --games 192 --eval-games 288
```

通用阶段写入 `shared/`，贤者阶段写入 `sage/`。检查点和对应的 `.pt.json` 写完才计为该轮完成。把 `PAUSE` 放到当前正在运行的阶段目录，训练会在当前轮保存后暂停。
