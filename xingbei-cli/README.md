# 星杯传说 CLI

零依赖规则引擎，运行环境为 Node.js 20+。

当前规则架构见 [游戏结构与接口](docs/game-architecture.md)：牌实体与六种区域、基础/专属牌继承、玩家组合英雄、牌承载效果、统一攻击/魔弹结算，以及明确的回合触发时点。规则代码统一英文标识；旧素材文件名由 `legacy-assets.json` 映射，原项目不修改。

日常`npm test`仅跑核心规则、牌实例/区域守恒、回合与触发器、异步响应和会话取消。英雄具体打法的评分场景不作为日常必跑检查；历史AI/训练接口检查用`npm run test:ai`，终端/呈现与开发场景检查用`npm run test:ui`，浏览器工具按本次修改手动选择。

当前前端重构的源码分析、阶段任务和验收标准见 [前端还原计划](docs/frontend-restoration-plan.md)。

P0 首批原版运行证据、实际布局差异及可重复截图命令见 [前端基准报告](docs/frontend-baseline-p0.md)。

```bash
npm test
npm start
HOST=0.0.0.0 npm run web
```

当前实现 3v3 六人局、自动回合、五个基于评分和风剑连击搜索的 AI、固定 150 张牌堆及全部 11 种基础牌。牌实例保留 `element`（系别）和 `fate`（命格）。

默认按座位顺序固定为红一、蓝一、蓝二、红二、红三、蓝三（红蓝蓝红红蓝），玩家控制第一个红方，即 0 号红一。后续规则与浏览器测试均使用这套六人坐次。默认控制 0 号玩家；也可以用 `npm start -- 2` 控制 2 号玩家。主动攻击命中获得宝石，应战攻击命中获得水晶；购买获得一个宝石和一个水晶；合成消耗三个星石、摸三张牌并生成星杯；提炼可把一至两个战绩区星石转为个人能量。已实现狂战士、风之剑圣、神箭手、封印师、守护天使和神官的十周年技能，默认阵容按该顺序入座。另已实现圣女、圣枪骑士、瘟疫法师、元素师、女武神和魔法少女。网页版和终端在开局时可选择这十二位中的任意一位；网页版“重新开始”也会重新选角色。选中其他座位的角色时与玩家座位交换，新增英雄替换玩家座位，默认六英雄通过交换位置保留阵容，固定阵营坐次不变。尚未实现技能的角色暂不进入选择列表。

终端界面快捷键：`Tab` 切换控制台/行动日志焦点，`PageUp`、`PageDown` 滚动当前面板；没有命令输入时也可用方向键逐行滚动。输入命令时方向键用于浏览和编辑命令历史。

网页版默认监听 `0.0.0.0:4173`（所有 IPv4 网络接口），上述命令也显式指定该地址，方便外部验证。启动后，本机访问 <http://localhost:4173>，其他设备使用 `http://服务器IP:4173`；`0.0.0.0` 是监听地址，访问时使用服务器实际 IP。如只允许本机访问，可运行 `HOST=127.0.0.1 npm run web`。网页与 CLI 共用同一套规则引擎，支持点击手牌选择目标，以及购买、合成、提炼、应战、魔弹、虚弱和爆牌弹窗。

网页使用原项目默认的 `music` + `nova` 外观，复用网格背景、字体、卡牌、头像、星石和治疗槽。已按实测公式还原六人座位、头像与手牌尺寸、战绩位置；当前十二位可选英雄包含实际技能；历史基础规则开发场景显式关闭英雄规则。运行资源已随仓库提供在 [`assets/`](assets/)，克隆后无需另行提供原项目目录；只有原版采集工具仍需要完整原项目。来源和许可见 [SOURCES.md](SOURCES.md)，实际验收范围及剩余差异见 [本次还原报告](docs/frontend-restoration-2026-10-10.md)。

默认日志收起，点击“记录”打开。选牌后可以点击“取消”、按 Esc 或再次点击手牌返回；应战与爆牌直接选择底部手牌。合成必须选择3个星石，提炼选择1至2个且不超过个人能量剩余容量；满足条件后点击“确认”才结算，选满不会自动提交，可取消或调整选择。战绩区宝石与水晶合计上限为5个，超过上限的新增星石不进入战绩区。整理手牌先将攻击牌、法术牌分别归组，再在各组内按系别、命格排序。

应战保持“选择牌 → 选择对手”，不增加确认步骤。选择对手期间可切换其他合法应战牌，当前选中牌上浮；点击对手后才使用该牌。再次点击当前牌、点击“取消”或按 Esc 返回应战选牌，“不响应”放弃应战。圣光无需选择对手，选中后上浮并显示“确认”，点击确认才抵消攻击；确认前可更换手牌、再次点击取消或按Esc。开发场景 `attack-switch` 可单步复现切牌，专项验证工具为 `tools/verify-responses.mjs`。

发起和传递魔弹同样先选牌、再点击唯一高亮目标，无需确认。目标按座次寻找本轮尚未参与的最近对手，全员参与后刷新本轮记录；魔弹真正传到你时才询问响应。传递选人期间可切换魔弹/圣光或取消，圣光选中后只显示“确认”，再次点击这张牌或按Esc撤回，也可切换手牌；只有未选择手牌时显示“不响应”。所有开发场景均使用默认六人坐次；`magic-linked` 是隔离的传递验证场景，由蓝三发起，验证蓝三→红一→蓝一→红二→蓝二→红三→新一轮蓝三。`magic-start` 用于验证发起，专项工具为 `tools/verify-responses.mjs`。

图片与字体使用浏览器本地缓存，有效期24小时；到期后通过 ETag 校验，未变化时返回304，无需重传资源。页面、脚本和样式不缓存，普通刷新即可读取界面更新。若修改图片素材后需要立即看到新图，使用浏览器强制刷新。缓存验证工具为 `tools/verify-resource-cache.mjs`，需要与前端验证工具相同的Playwright环境。

开发场景入口：<http://localhost:4173/web/dev.html?scene=opening>。工具栏可切换场景、重置、暂停/单步AI和导出状态；正常游戏不显示这些工具。`attack`、`magic` 场景点击单步进入响应。暂停在回合边界生效，需要应战时单步会等待人类输入。

当前六人开局布局对照：<http://localhost:4173/review/restoration/2026-10-10/six-compare.html>。四视口截图、几何检查及隔离准备说明见最新实施报告。

首批四人原版/新版历史截图对照：<http://localhost:4173/review/restoration/2026-10-10/compare.html>。浏览器采集与验证工具需要环境已有Playwright，未引入生产依赖；命令及证据说明见本次报告。

从其他设备查看开发场景和截图对照时，将上述地址中的 `localhost` 换成服务器实际 IP，端口和路径保持不变。

通过 Tailscale 访问本机时，使用 <http://100.110.150.77:4173/>（该 IP 是当前验证机器的 Tailscale 地址）。本服务仅提供 HTTP，不能直接使用 HTTPS。

当前验证服务器使用持久的用户级systemd服务，每分钟检查GitHub的`main`分支。新提交通过规则测试和隔离启动检查后切换，启动失败自动回退；运行目录为`~/.local/share/xingbei-deploy/current/xingbei-cli`，不覆盖开发工作区。安装、配置、暂停和失败重试见[服务器自动更新](docs/server-updates.md)。

```bash
systemctl --user status xingbei-web.service
systemctl --user start xingbei-update.service
systemctl --user list-timers xingbei-update.timer
node ~/.local/share/xingbei-deploy/update-server.mjs --status
```

测试时使用 `TEST_MODE=1 HOST=0.0.0.0 npm run web`，页面顶部中央显示 `package.json` 中的版本号（本次体验版为 `测试 0.7.1 + AI 1.7.0-preview.2`），正常启动时不显示。当前外部验证后台服务已开启此开关；修改版本号或开关后需要重启服务。当前运行所需素材已纳入 `assets/`；完整原项目与浏览器截图产物仍保留在本地。


当前测试版本v0.3.0加入对局动画，范围、来源和接口见 [动画说明](docs/animation-restoration.md)。开发页新增连续中毒、圣盾抵消、重摸、对手摸牌和第五杯场景；工具栏支持暂停/播放效果、单步效果及结束当前动画。遵循系统减少动态效果偏好，正常对局不显示这些调试工具。用户现已授权提交本批改动并直接push到main。

当前测试版本v0.3.1补充无牌响应的取消步骤、attack/spell伤害类别、public/hidden弃牌可见性，以及场上牌在整条结算完成后的统一弃置。规则接口见docs/game-architecture.md。

v0.3.2将无牌响应的提示和按钮统一为通用标题与“不响应”，响应界面不按合法牌数量分支。


六英雄实现和逐goal验证见[实施记录](docs/hero-implementation.md)。神箭手狙击直接补到5张，隔离场景上限4验证爆牌；正式默认手牌上限仍6。额外攻击可以点击“结束回合”放弃，终端命令为`end`；终端`skill`列出当前合法英雄行动。治疗槽按神官上限6和队友实际超上限值展示。六个goal各保留独立提交，PR #2已按用户授权合并main。

六英雄现在分别继承`src/hero-base.js`中的Hero，复用绑定、主动/应战攻击与独有技判断。`src/triggers.js`维护六个玩家Map和120个基础攻击/伤害订阅槽；事件只查发起者/承受者，优先级越大越先执行。同一优先级按稳定顺序执行。动态技能使用`hero.addSkills(...)`/`hero.removeSkill(id)`，状态牌授予技能随区域移动自动注册/注销。具体声明方式见[规则结构](docs/game-architecture.md)。

浏览器验证与原版采集工具已整理为8个脚本，当前命令、用途和旧入口迁移见[tools说明](tools/README.md)。应战、魔弹、无牌响应/暗弃统一运行verify-responses.mjs；四人历史采集脚本已移除，历史证据保留。

## 确定性 AI（v0.6.0）

六角色牌值、爆牌留牌、技能选人/分牌、提炼与风剑三刀规划已接入网页版和终端。策略、限制及可复现对战结果见 [AI 说明](docs/ai-policy.md)。`rankAiActions` 可检查候选行动的评分，规则结算仍由 Game 负责。

## 开局模式（v0.6.1）

开局可选择正常游玩、测试游玩或观战游玩。测试模式提供摸牌、选牌弃置、双方士气±1和回合结束后重复自己回合；观战模式为0号AI选角后全部由AI执行，支持暂停/继续。测试和观战在各角色下方显示手牌图标。使用范围、暂停和验证记录见 [模式说明](docs/play-modes.md)。

## 行动记录与命格（v0.6.2）

六英雄技能记录补齐目标、费用、牌的去向和实际结果。测试／观战显示交牌、摸牌与暗弃的具体牌面；正常局保持隐藏。手牌缩略图右上角增加命格。逐技能核查和验证结果见[行动记录说明](docs/action-history.md)。

## 随仓库提供的资源（v0.6.3）

图片和字体位于[`xingbei-cli/assets/`](assets/)，保留原路径、原许可、来源及SHA-256清单。服务器从本目录读取，页面URL和24小时本地缓存机制保持不变。当前收录39个文件，共20,809,828字节；只包含运行所需资源，未上传完整旧项目或历史截图。

## AI v1.5
