# 无法行动的拦截与判负档案

按玩家合法已知信息判断确定性。真·摹影耗尽可行动手牌、兽魂警戒移除行动者最后一张牌会在支付前拦截；强制弃牌存在安全选择时，只开放能继续行动的组合。若实际执行造成恶意无法行动，在启动流程结束检查责任方并判负。随机启动摸牌导致无法行动则明弃全部手牌、重摸相同数量，直到可行动，不重复启动。

初版预拦截接入真·摹影、兽魂警戒，后续扩展见下文。2026-11-13新增统一启动选项检查，既有明确的英雄规则约束仍保留。不能将临时失去手牌一律视作恶意；对他人的暗手牌不检查牌面来决定拦截。

每次实际判负生成独立 JSON 档案，包含初始配置、责任方、受影响者、技能、判断依据、完整回合状态、六人全部手牌与英雄状态、所有牌实例及区域、抽牌顺序、战绩资源、行动日志、牌移动和选择记录、公开历史。档案为深拷贝，不随游戏继续修改。

- 终端：默认 `~/.local/share/xingbei-logs/inability/`，可用 `XINGBEI_DIAGNOSTIC_DIR` 指定目录。
- 浏览器：自动下载 `xingbei-inability-时间戳.json`，同时尝试保存在当前站点 localStorage；浏览器配额不足时仍下载。
- 训练：当前运行的诊断目录内 `inability-forfeit-种子-序号.json`，另含规则版本、决策序列和复现命令。

这些文件含完整隐藏信息，仅供规则排查，不加入普通公开日志或模型观测。判负属于正常终局并留档；未知规则异常仍按训练约定暂停并保存现场。

## 2026-11-10启动弃牌保留行动

启动已经开始、普通行动尚未执行时，爆牌选择必须保留一种实际合法行动，只要存在这样的留牌组合。判断同时考虑可用手牌和英雄技能。随机摸牌后所有留牌组合都无法行动时，仍在完整结算后沿用强制换牌。已完成行动及其他玩家的普通爆牌沿用原选择范围。

- 魔枪暗之解放后的爆牌保留可用攻击，拦截弃唯一水刀后只剩不可使用法术的选择。
- 苍炎魔女之怒摸牌后保留可用攻击，覆盖弃唯一风刀及同时弃暗刀、地刀留下圣光的两例。
- 异教徒献祭获得水刀后，拦截弃水刀只留五张圣光的选择。已有合法独立技能时按实际行动能力判断。
- 格斗家斗神天驱的暗弃到三张接入`preserveAction`，拦截弃光攻击只留三张圣光。

引擎在移动牌和扣爆牌士气前校验，网页和终端共用规则。网络分步选牌通过惰性完成性搜索过滤下一张可选牌，复用按选牌集合缓存的结果。规则AI也只提交满足约束的爆牌选择。

本批152项核心测试、17项AI接口测试、8项UI合同通过。五份原存档分别保留230、114、226、354、353步选择后，在原非法选项处拦截并改选，后续全部正常终局。存档及脚本验证结果见本机`/tmp/xingbei-overflow-fix/replays.json`。1440×900桌面和390×844触屏以浏览器注入初始手牌，完成魔枪及苍炎真实启动、选择、撤回及确认流程，验证唯一可用牌禁选、多选时保留最后可用牌以及确认前牌不移动；四组流程通过，无控制台、脚本及资源加载错误，证据位于同目录`browser.json`及截图。本批修改位于工作区，持续训练的独立快照需要由主线程另行接入。

验证：核心 Node 测试及训练接口测试；1440×900、390×844 隔离浏览器验证拦截提示、返回操作、完整 JSON 下载。隔离验证不代表所有英雄自然对局已经验收。

## 2026-11-04 用户裁定与选择约束

- 染污者弃2仅在手牌超过2且有可使用牌时开放，选牌组合必须保留至少1张可使用牌；否则摸2。
- 红衣主教驱魔式不得选择只剩1张非圣命格牌的自己。权能逆位变身、王车易位返回路径已核对：保留圣遗物、银制子弹与宝珠实例，新旧技能订阅随英雄替换更新。
- 星坠盖最后一牌后，可选启动摸1；没有可用牌时黄金律必选。交换仍自由，完整技能结束才按最终行动能力换牌。为获得行动条件而启动时，盖牌分支必须摸1。
- 传教士根据路标持有者是否有手牌约束摸牌和自弃；持有者空手、自身也空手时不可传道，自身只有1牌必须摸1并尽可能保留可用牌。持有者有牌且传教弃后空手，必须给予接收者可用的牌（存在时）。交换与事奉完整结束才判断换牌。
- 魔眼仅3张以上且有可用牌时开放弃牌路线；自弃保留可用，盖牌自由。完整结算后，有雷充能可雷光散射就不换牌，否则无合法行动时换牌。
- 充能摸0至4自由，空手时禁止摸0；盖牌前若手牌全不可用先明弃重摸，再盖牌且必须留至少1张可用。AI优先摸不超过手牌空位的数量，上限4。
- 兽灵只剩1牌不能弃；全不可用时必须摸1，之后允许换牌。
- 尚未启动、不可买合且无普通行动时，如果存在可供给行动条件的启动路线，不开放直接换牌；可选择提炼或启动。启动后仍按最终行动能力处理，不重新触发启动。

传教旧误判的实际原因是中间移牌记录的`inabilityCause`延续到整个启动结束，不是直接在弃牌中途判负。上述允许自由交换/盖牌的技能在完整结算末调用`allowActivationRefresh`消除该过时归因。通用`ensureActionableHand`检查技能行动（包括雷光散射），只有充能盖牌前显式要求手牌本身可使用。

本批不增加长期具体场景测试：现有148项核心、14项AI/训练接口通过，临时脚本核对选项与牌实例守恒；12局短跑覆盖72英雄。完整异常和判负归档继续保留，不宣称其他英雄所有分支已杜绝无法行动。

## 2026-11-12 四类启动判负与血剑评分异常

本轮 `morale-only-20261112-001a9cc2aa` 的21份无法行动判负档案分为魔剑士8次、传教士7次、乐团首席5次、魔枪1次。本批只修改工作区，不修改独立训练快照、不恢复训练、不部署服务。

- 暗影凝聚、幻影星辰的启动自伤明确声明需要保留行动供给。自身空手、尚欠普通行动且没有独立合法技能时，治疗最多抵消到剩余1伤；有手牌或独立行动时保留原治疗范围。限制在所有治疗前触发结束后生成选项，并校验提交值；该标记不传播到嵌套伤害。随机摸到不可用牌，仍在完整启动结束后处理强制换牌。
- 属灵恩赐在发动前检查每种实际能量支付及弃牌后的合法行动。原0至1手禁止发动的裁定保留；攻击加圣光时只允许弃圣光，可用法术也能构成保留方案。费用支付不能消耗唯一后续技能所需的宝石。无安全方案时不发动、不付费，不能把“还有一张牌”当成可行动。
- 协奏曲中的独奏使用同一支付／留牌检查，不能把最后可用手牌放成乐章。支付后重新生成合法选牌，选牌用途标为cover。攻击／法术行动结束后的独奏不受这项续行动限制。当前协奏曲移除X再加X−1，最终音符不足3，不存在随后新乐章恢复手牌的分支；未将此结论泛化到所有盖牌技能。
- 共用检查仅投影本人手牌、实际支付后的能量、增疗后的治疗及已启动状态；不执行触发、不移动牌、不读取未知牌序。已有规则明确允许的随机恢复流程不变，实际判负及完整归档兜底继续保留。

血色剑灵种子831131116是另一类程序异常：能力估计产生小数伤害，模拟爆牌使士气成为期望小数，而旧终局预测将它直接用于数组长度。本地已有的修复将小数士气按相邻整数的概率分布计算，本批保留该修复并补充等价加权检查；不将真实规则士气取整、不吞掉评分异常。根据原档案在内存恢复当时局面，3个行动评分均为有限值，花瓣之舞选择完成，评分前后真实状态不变。此验证是现场状态恢复后的评分核对，不是从开局完整重放，也不是整局强度评测。

## 2026-11-13 统一启动选项检查

`TurnFlow.activate`通过`src/resolution/activation-guard.js`包装完整启动生成器。自身选牌、目标、治疗抵扣，以及其他玩家在启动链里的响应都经过同一入口；没有为暴食、红莲或魔剑士设置特例白名单。启动中的爆牌选择也由生成器接收并执行，防止客户端在外部结算而绕开检查。

判断的是“选此项之后，完整启动是否必然空手且没有合法行动”，不是“操作中途有没有变成0张”。推演在独立游戏副本重放已发生的选择，探索剩余合法分支；只在所有已知分支均不可继续时过滤选项，并在提交前再次校验。原局不支付费用、不移动牌、不推进随机数。已有合法无手牌技能行动仍允许；必然非空但牌不可用的明确约束继续由原有行动能力接口处理。

推演不使用其他人的私有牌面和未来牌序：访问未知牌面、未来本人的随机摸牌、无法安全复制的动态技能或不支持的请求，都视为无法证明，允许该选项。每个候选最多96个搜索节点、64层决策；组合数过大也不穷举。这是保守预防，不是所有英雄任意长结算链的完备证明。不能证明的情况保留结算末检查，不能把未知当成必然恶意。

实际启动后仍无合法行动时：确定责任方判负并保存完整档案；伤害被转移、导致必要摸牌供给消失时记录转移技能的操作者。尚有手牌的随机失败依然强制换牌；空手无法按原数量恢复时正常判负归档，训练继续下一局，不再进入零候选错误。其他程序错误仍停止，未添加吞掉任意异常的兜底。

两个原始存档按完整选择序列重放：`860012508`在第373次选择拦截暴食弃牌接走红莲的4点自伤，红莲随后有4手；`850118394`在第216次选择拦截接走魔剑士的1点自伤，魔剑士随后有1手。均在费用支付前拦截，暴食保留原手牌，无判负。原始现场保留在旧训练目录，验证证据在`~/.local/share/xingbei-ml/activation-guard-20261113/`。160项核心规则检查通过，另12局完整评分AI对局正常终局；这些不是模型强度评测。
