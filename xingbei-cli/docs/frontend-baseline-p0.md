## 环境与实际进入路径

环境为 Node.js 22.22.1、Python 3.14.4、Playwright 驱动的 Chromium Headless Shell 151.0.7922.10。视口 1440×900、DPR 1、浏览器缩放 100%、语言 zh-CN、时区 UTC。原版游戏内部另有 1.05 倍缩放。

原版通过仅本机可访问的 Python 静态服务运行，新版通过已有 `server.js` 运行。静态服务不实现原版文件读写 API，影响见加载问题表；不能据此声明原版平台服务也通过验证。

复现路径：

1. 新建独立浏览器上下文，打开原版，确认本地首次启动说明。
2. 等待新手向导出现并完成入场过渡，捕获教程界面。
3. 点击“跳过向导”，页面重载，进入“星杯传说”默认 2v2 选角。
4. 捕获选角页面，选择“一”号位，再选择“狂战士”。
5. 等待 `gongJiOrFaShu` 事件和本人 4 张手牌，捕获 S01。
6. 点击第一张手牌，确认 `ui.selected.cards.length === 1`，捕获 S03；再次点击取消，再打开“选项”捕获菜单。

采集上下文使用种子 20260905 覆盖原版 `Math.random()`，用于稳定候选角色和洗牌；新版因使用 `Date.now()` 给引擎设种子，在独立上下文中固定该返回值。这是开发采集条件，不是对生产代码的修改，也不保证两个不同引擎发出相同的牌。

S01 原版选到狂战士，其他相对座位为魔法少女、吟游诗人、剑帝。原版角色技能仍然存在，不能把其牌面技能文字直接当作新版已经实现的功能。双方引擎能力的差异在后续场景适配与业务接入中分别记录。

## 如何复现

从工作区根目录分别启动：

```bash
python3 -m http.server 4180 --bind 127.0.0.1 --directory xingbei-1.6.7-source
HOST=127.0.0.1 PORT=4181 npm --prefix xingbei-cli run web
```

采集脚本需要开发环境可用的 Playwright 与匹配的 Chromium。未给项目添加生产依赖；可通过 `PLAYWRIGHT_MODULE` 指定现有 Playwright 模块目录，通过 `BROWSER_EXECUTABLE` 指定浏览器文件。已按 Playwright 默认方式安装时可省略这两个变量。

```bash
node xingbei-cli/tools/capture-frontend-baseline.mjs
```

输出默认写到带时间戳的 `xingbei-cli/artifacts/frontend/p0/` 子目录，也可传入自定义输出目录。目录内已经有 `run.json` 时拒绝覆盖。容器确有需要时可设置 `BROWSER_NO_SANDBOX=1`；正常环境不必设置。

查看本批对照页：

```bash
python3 -m http.server 4182 --bind 127.0.0.1 --directory xingbei-cli/artifacts/frontend/p0/2026-09-05
```

浏览器打开 `http://127.0.0.1:4182/compare.html`。DOM 快照仅供下载排查，不作为可运行游戏入口。
