# 版本化 AI 与评测

AI 版本独立于应用 package.json 版本。v1.0 来源为 Git 提交 `31007a8d38088a6d8678587f931c45fa2d2fb96a`；冻结源码在 `src/ai/v1.0/`，manifest 固定五个文件哈希，仅入口的相对导入路径与原提交不同。规则引擎共用，版本冻结不意味着冻结规则；跨规则版本比较必须重新评测。

## 使用与边界

`getPolicy(id)`（`src/ai/versions.js`）提供行动、响应、技能、弃牌、留牌与同步执行入口。独立运行使用此注册表的 `runAiAction`，不要直接调用冻结源码内依赖历史引擎默认值的兼容入口。`runner.js` 在同步执行期间显式绑定该版本的嵌套决策，完成或报错后恢复原处理器。

- `v1.0`：冻结基线。
- `v1.2`：当前CLI/Web生产共用默认，稳定映射fusion-1；发布审查见`ai-v1.2-release.md`。
- `v1.1`：历史稳定版本，严格等于下述read-1；防御/英雄实验开关关闭。
- `read-1`：属性概率+软历史，权重1；防御/技能/弃牌与基线完全相同。
- `fusion-1` / `experimental/fusion-1`：吃刀公开代价、命中收益与有限英雄攻击序列融合候选；已验收为稳定v1.2默认，候选名称仍保留。
- `experimental/read-1`：旧历史候选的独立实验别名，旧报告保留。
- `read-prior`：关闭历史的基础对照，不作为产品终点；`read-half`：半权重；`read-off`：关闭读刀，应等价v1.0。
- `defense-1`：仅防御取舍；`heroes-1`：仅小幅英雄补分。这两个都是未获推荐的实验策略。
- `read-defense`、`all-1`：用于未来组合消融的开关，目前未做胜率验收，不推荐。

`public-history.js` 只记录摸/交/弃的数量事件、公开牌当时的属性，以及非强制、可应战攻击的命中。不会读取渲染快照、隐藏日志或牌库；暗弃、交牌不记录牌ID/属性。历史窗口256条，按摸牌、离手、回合流逝衰减；吃刀只增加有限缺牌倾向，绝不判定“必无同属性”。新局使用新的历史对象，WeakMap缓存不会串局。

`reading.js` 的先验来自固定公开牌表，含普通同属性应战、暗灭和圣光。读取真实引擎允许的候选行动，再按目标手牌数量、公开信念及英雄已知响应限制估计命中率；不模拟他人手牌、不消耗规则随机数、不改变规则。权重同时按预计士气损失放大，仍保留v1.0的星杯/资源/连击等行动竞争，不是最大命中率的单目标策略。概率为启发式，未进行真实人类行为校准。

`defense.js` 与 `threats.js` 为独立实验：包括吃刀与响应成本、圣光/暗灭保留、封印暴露惩罚、狂战即时伤害以及神官领域、神箭法术/狙击、风剑追击的公共风险。神官、神箭、风剑威胁只能依公开资源和手牌数估计，不能知道技能费用牌是否在手。当前实验显示防御收益为负，不能启用到推荐策略。英雄小幅估分也没有足够收益；不宣称完成最优的六英雄策略。

## 评测命令

从仓库根目录运行；不需要安装依赖：

```bash
npm --prefix xingbei-cli test
node xingbei-cli/tools/evaluate-ai.mjs read-1 v1.0 tune 40 /tmp/read-tune.json
node xingbei-cli/tools/evaluate-ai.mjs read-1 v1.0 holdout 200 /tmp/read-holdout.json
node xingbei-cli/tools/evaluate-ai.mjs read-1 read-prior holdout 100 /tmp/read-vs-prior.json
node xingbei-cli/tools/evaluate-ai.mjs v1.0 v1.0 selfplay 10 /tmp/selfplay.json
```

参数依次为候选、对手、种子集、每阵容种子数、输出文件、可选逗号分隔阵容名。输出使用新文件，避免覆盖既有证据。未来注册v1.2后可以分别对v1.0、v1.1运行；不假设胜负关系传递。旧 `benchmark-ai.mjs` 是历史单文件AI比较工具，不支持这些模块化版本，不用于新结论。

默认六组阵容：强攻（狂战/风剑/神箭）、法术（神箭/封印/神官）、支援（封印/天使/神官）、混合（狂战/天使/神官）、节奏（风剑/封印/天使）、压迫（风剑/神箭/神官）。每组双方英雄完全一致，固定红蓝蓝红红蓝坐次，英雄顺序按seed%3轮换。每种子同一初始牌序分别从座位0与1起手，并各交换新旧策略颜色；不同策略导致后续牌序消耗分歧是正常因果结果，不强行重新发相同手牌。

所有同步/异步请求显式按玩家所属策略路由；爆牌传入该策略算出的索引，不使用引擎的全局“ai”回退。评估器的真实初始手牌记录仅写入结果，不反馈给策略。`tools/ai/privacy.mjs` 仅是可被反射绕过的直接访问诊断，不能作为安全边界。新策略注册入口统一通过 `observation.js` 的显式数据副本：不传原始Game、隐藏手牌或未来牌序。`v1.0`保持冻结实现；其行为由单独访问诊断及反事实对照检查，不能声称源码已改为新隔离架构。引擎修改仅添加公开观察记录；关闭观察的基线对局与开启时规则、随机轨迹和指标一致。

## 指标和局限

胜率为主；500回合截断单列，得分率按截断0.5；引擎无自然平局规则。95%区间为4000次固定重采样种子的整种子簇percentile bootstrap，同簇保留所有阵容/颜色/起手，非独立局Wilson区间。分阵容区间未作多重比较校正，仅描述。

命中数以攻击命中时点计，包括主动和应战，盾抵消不算命中；伤害为治疗后真实伤害量，友伤作负值，分别记录攻击/法术；它会导致摸牌，不等价于士气损失。士气损失记录所有实际下降（包括星杯等），资源记录实际新增宝石/水晶（上限溢出不计），星杯为最终数量。速度和局数不同会影响总伤害，报告每局均值而非仅看总量。

固定种子、六组阵容、v1.0对手只是有限评测分布，不能外推真人强度、全部20种三英雄组合或其他策略。历史缺牌模型未做概率校准，也未推断策略型主动吃刀的个体差异。初始镜像阵容合法，但正式默认六个不同英雄分属两队；默认局与其他非镜像阵容的胜率尚未量化。

融合候选的规则依据、一次性冻结门槛、全新种子及不发布条件见 `ai-fusion-preregistration.md`，本轮结果见 `ai-fusion-results.md`。control/fusion种子集运行后即已使用，未来不得作为未见留出。
