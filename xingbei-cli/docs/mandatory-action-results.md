## 根因与边界

原策略把普通 pass 当成零分候选，真实引擎 `TurnFlow.end()` 没有检查普通行动是否完成，甚至调用 endAction 补成完成。由此人类界面不提供的普通 pass 能经AI/评测直接结束回合；合法动作全为负分时最容易触发。此修复不是循环检测或判和。

现在引擎拒绝结束未完成行动及未完成强制弃牌的回合。共同适配层限制所有注册历史/实验策略的候选，过滤普通 pass；即使全部评分为负仍选择最高分合法行动。旧策略完全遗漏合法选择时，按共同枚举顺序取一个合法动作，标记 `required-legal-action`（未估值，不伪造分数）。没有合法动作则报规则状态错误，绝不补pass或伤害。

冻结策略目录逐字节保持原样。`traceDecision/replayTrace`仍是原始历史诊断，可能含非法普通pass；不得直接把它们当执行策略。正式`getPolicy`/`src/ai.js`统一经合法性适配。搜索中额外攻击的零分停止分支保留，因为那是规则允许的放弃；初始普通行动候选不能用该分支。响应的null与强制请求分别遵守现有规则校验。

人类CLI/Web、自动执行器和评测/辅助工具的pass分支都只调用受校验的额外行动放弃。正常API不接受普通pass。现有开发场景、测试模式、暂停/单步、重复已结束回合均保留；未添加默认启用的调试跳过，也未把调试行为混入评测。此前没有独立普通调试pass命令，原end漏洞不能继续作为正式接口。

## 行动分类与资料限制

攻击牌、法术牌及声明为attack/spell的主动英雄技完成真实结算后满足行动。启动技只设置activationDone，不设置completed；神官契约导致预选失效的真实回归确认仍必须重选并完成行动。购买、合成、提炼原本均是special路线，消耗一次行动；本次未把提炼变成免费附属。

无法通常出牌时保留已有规则：0–3张可购买；当前六英雄手限6，4–6张全不可用且无合法英雄技时可展示并换牌。合法提炼还要求战绩星石、个人能量容量和1–2颗支付。用户最新列举“攻击/法术/购买合成”没有明确提炼与无法行动刷新；这里只保留仓库既有规则，不能据此宣称用户穷尽认可它们。若最新原话意在删除这两类，需父线程确认该具体差异，不能偷偷扩大或删改规则。

本checkout缺少AGENTS指向的原版源码；依据为用户明确的不可跳过规则、仓库docs/game-architecture.md、SOURCES.md映射及真实引擎。未声称重新核验原规则全文。未来手限>6、canActWithSkills=true却无可用技、启动后资源变化可能暴露空候选，应明确报错并核规则，不补跳过。
