# AI 实体管线改造

目标：优化训练输入，核查英雄机制，接入共享实体网络。保留终局胜负奖励，只做必要接口、隐私和性能检查。当前状态：**本次架构与管线改造完成，尚未替换线上 AI**。

## 已实施（2026-11-02）

- 训练候选复用引擎的变长牌组费用、组合限制、目标数量和个人能量上限。旧教师对虚弱返回 null 时，按引擎实际行为编码为 skip。
- `src/heroes/<hero>/observation.js` 声明18位已实现英雄的持久状态及可见性。未知状态字段直接报错，避免默默遗漏。公共、持有者私有字段分别处理；当前牌引用仅用于公开创建的五系束缚。
- `training/entity/observation.mjs` 独立 `entities-v2` 接口：相对座位玩家、团队、牌、技能、英雄状态、回合/额外行动、本人行动预留、当前问题、最近32条公开行动。候选引用本次观测实体，不传内部牌ID，不重复展开整份手牌。
- `training/entity/model.py`：显式词表、关系编码、两层 Transformer、候选评分；策略/价值网络参数分离。价值目标仍是终局±1。模型和词表一起保存；schema不同拒绝加载。当前无规则偏置、特权信息或中间奖励。
- worker 按请求 opt-in 新schema，旧schema2保持兼容。独立采集、监督训练和完整对局推理入口已打通。

## 首次必要验证

- 两项新检查：三阵容18个座位隐藏信息扰动后观测逐字节相同；三阵容完整对局候选引用有效。旧教师接口检查通过。未覆盖未来尚未实现的盖牌机制，不能称全部未来英雄隐私已验证。
- 同一批6局919次决策、9267个候选：旧编码约681.9ms，新编码约85.7ms；JSON数据18,317,367→12,147,036字节。整体含教师、双编码、序列化和写文件约3.14s；教师约2.11s。仅是单进程小样本编码比较，不是端到端训练加速比例，也未测候选生成独立耗时。
- 新网络571,394参数，GPU完成4次更新；按完整对局划分770条训练、149条验证决策。模型恢复输出完全一致。随后CPU加载模型并通过worker完成第三批英雄整局，85次决策。**仅证明链路运行，不构成强度或表示优劣结论。**

## 架构边界与后续

原版六个包提取到103条角色定义，含扩展和改版；清单见 `ai-entity-hero-inventory.md`。不把“60英雄”硬编码为容量。已识别必须覆盖的机制：计数/形态、独立牌效果及施加者、公共或私有盖牌、可当手牌使用的旁置牌、展示后保留的私人记忆、限定属性的额外行动、指向固定对手的持续效果、顺序结算和胜利即停止。

本次实施顺序（完成证据见各批记录和末尾审计）：

1. 对照清单补完逐技能语义审查；明确已知牌记忆、盖牌/旁置区域可见性、关系顺序及完整决策上下文。当前并未实现未来英雄的这些规则。
2. 扩展实测到编码、IPC、候选、推理的分项吞吐；保留可复现数据，优化实际瓶颈。
3. 用相同信息和固定整局数据进行结构化网络/旧表示监督对照，记录各决策类型指标和未知词覆盖，不能用旧表示缺少状态造成的优势冒充网络改进。
4. 接入批量训练和推理；终局奖励自博弈及独立强度评估后才考虑更新服务。暂不做 oracle critic、辅助预测、六种性格或大搜索。

## 上下文补齐（第二批）

- 规则引擎提供随嵌套触发恢复的 `activeTrigger`，只供适配器读取；不改变技能选择或结算。实体编码显式读取白名单，补齐技能未显式传参时的目标、伤害、时点，以及命中/防御限制等标记。未知对象和隐藏牌数组不透传。
- 攻击和魔弹请求增加链起点/深度，魔弹增加方向；公开弃牌进入可见实体，暗弃牌仅贡献弃牌总数。目标关系按位置编码，避免交换目标顺序后表示完全一样。
- schema 升为 `entities-v2`；v1原型权重不兼容。实战推理仅调用策略，不再计算无用的价值网络。
- 三项实体检查和现有92项核心规则检查通过。相同6局919决策重新测量：旧编码677.4ms，新编码168.9ms；补足公开弃牌后JSON体积为20.6MB，超过旧版18.3MB。此前“编码约1/8、传输更小”仅适用于首批不完整输入，**不是当前完整输入结果**。后续需要压缩传输和拆分推理计时。
- v2 GPU四步更新及精确恢复通过，仅验证运行；仍未开始正式强度训练或表示A/B。


## 稀疏传输与批量推理（第三批）

`wire.mjs` 按检查点词表把实体预编码为特征索引、权重及关系；词表SHA-256必须匹配。无哈希碰撞或观测裁剪，raw模式仍可诊断。训练数据在词表建立后一次预编码，优化器各步不再重复解析类别字符串。`pool.py` 用持久Node进程生成独立对局，由一个Python进程合并待决策请求进行GPU推理；没有共享座位私有状态。

必要检查：32个同源决策的raw、Node稀疏传输、Python缓存预编码产生完全相同的张量；raw和稀疏的策略输出完全一致。旧worker兼容检查4项通过；GPU缓存训练两步及精确恢复通过。

性能证据见 `ai-entity-performance.json`：

- 固定32决策450候选，序列化736,383→279,991字节。Node额外打包约5.06ms；Python解析3.10→2.02ms，组批14.90→9.55ms。不是无成本压缩，部分工作移到模拟进程。
- 4进程、GPU批量推理、6个相同seed/阵容对局：双方均656次决策/7238候选，最终结果完全相同；raw约1.039s，稀疏约0.954s。worker输出字节13,504,865→5,242,836（未计启动时发送词表的单次成本）。仅小样本，不将约9%的差异称为稳定训练提升。
- 单决策网络推理CPU约0.33ms、GPU约0.40ms；32批次GPU约0.57ms。GPU优势需要合批；这些网络计时不包括组批/传输。结果没有推出新的AI强度结论。

## 全角色机制审查与候选顺序（第四批）

已审阅六包103角色条目、605技能/状态条目的说明，并补查跨包复用、继承、标记intro和预言容器源码；逐英雄架构要求与源文件哈希见 `ai-hero-mechanism-review.md`，统一契约见 `ai-observation-schema.md`。这是表示能力审查，不是未实现角色的规则验收。

## 同信息监督对照与训练恢复（第五批）

`train.py` 现在支持 `--resume`，恢复模型、优化器、CPU/CUDA随机状态、Python采样状态、整局划分及累计步数，验证数据SHA-256、架构和batch。`--steps` 表示额外更新次数；输出已有文件拒绝覆盖。旧原型检查点没有训练元数据，不能冒充可恢复检查点。CPU“连续4步”与“2步后保存、恢复再2步”参数、优化器、随机状态和累计步数完全一致；没有声称GPU跨硬件/不同批量调度位级复现。

监督对照使用同一24局、3698次决策，整局划分2745训练/953验证决策，验证覆盖三批18英雄。两架构均seed17、batch32、AdamW 3e-4、200次更新、终局±1价值标签、相同教师。哈希对照复用旧CRC32特征方法，但接收同样的完整实体观测，并展开候选所引用实体；它是约59万参数的适配MLP，不是冻结1.5模型，不额外获得EMA历史。实体网络约61万参数。

## 终局奖励策略更新与完成审计（第六批）

`reinforce.py` 复用持久模拟进程池，冻结本轮策略完成采样后再更新。模型按合法候选的分类分布采样，记录选择、旧对数概率和旧价值；只给完整结束局标记所属团队的最终±1回报。使用截断比率PPO与未折扣的终局蒙特卡洛优势；没有中间局面奖励，不给选牌/选目标子步骤额外时间折扣。熵项仅用于探索正则，不是局面奖励。

策略和价值参数独立；训练允许双方共享同一网络但输入始终为各自可见观测。支持按轮轮换规则AI和自对弈。当前不做特权critic、六种性格、辅助隐藏牌监督、长期循环记忆、搜索或历史神经模型联赛；这些是后续可选增强，不是这次实现的强度承诺。

每个完整轮次保存独立检查点（权重、优化器、随机状态、轮次与采样配置），可从该轮边界恢复；不承诺中途一半对局的恢复或并发调度的逐位确定性。输出不覆盖已有文件。任何全为截断局的批次都会报错，不将其当输局训练。

必要实跑：

- 与当前规则AI对战6局全部结束，386条模型决策、13次更新。
- 从该检查点恢复后进行6局自对弈，全部结束，1014条决策、32次更新。
- 检查两次权重均发生变化、轮次从1恢复到2、终局奖励按实际座位团队对应；人为截断输入被排除。
- 更新后的检查点通过6局模型推理。最终92项现有核心规则、4项实体接口检查通过；未进行无关前端截图或历史全量AI测试。
- 额外的可选Node分项计时覆盖候选生成、等待决策、牌守恒检查。最终6局样本各进程累计候选34.6ms、守恒检查41.1ms、等待决策3074.2ms，累计生命周期3324.9ms；这些是并发进程重叠的墙钟时间，不能与约1.03s端到端耗时直接相加或当CPU百分比。

证据见 `ai-entity-terminal-check.json`。以上仅证明终局学习链路与恢复可用，不表示当前实验权重强于规则AI、旧混合模型或真人。当前线上服务仍使用原有基线，不自动部署实验权重。
