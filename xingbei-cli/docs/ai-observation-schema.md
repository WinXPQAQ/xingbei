# 星杯 AI 统一观测与动作规范

本规范根据六个原版角色包的103条角色定义、605个技能/状态条目制定，审查记录见 [ai-hero-mechanism-review.md](ai-hero-mechanism-review.md)。目标是同一共享网络支持所有英雄，不将不同英雄拆成不同网络。当前运行编码为 `entities-v3`，只开放已实现18英雄；未来机制的契约不代表规则已经实现。

## 1. 信任边界

规则引擎负责状态、合法性、时点、随机数和结算。训练驱动只枚举引擎允许的命令，模型只能返回本次候选的索引。模型不能调用Game、读取中文日志、浏览器测试手牌、未来牌序或其他人的隐藏牌面。

`encodeEntities` 是可信适配器，白名单复制字段，返回脱离引擎的JSON。牌引用变成本次实体数组索引，玩家引用变成相对座位0..5，0恒为决策者。多人目标有顺序；自身/敌方相对阵营保持，不把座位偏置编码成英雄强弱。动态行动顺序是额外信息，不能改变“相对座位”物理含义。

隐私分为两层：观测构造不得夹带未知内容；候选、规则分数、缓存和后续模型也只能依赖同一合法信息。修改未知牌面、未知牌序、日志等，不应改变合法观测及其策略输出。不能只在神经网络末端遮罩泄漏字段。

## 2. 当前实体与候选

每个实体结构为 `{kind, categorical, numbers, refs}`。类别使用检查点内固定词表，数值保留真实数量后作带符号log1p变换，引用只指向当前可见实体。没有特征哈希。未知词映射到显式unknown，需要在正式训练记录未知率，不能偷偷扩词后硬加载旧权重。

| 实体 | 当前内容 |
| --- | --- |
| player ×6 | 英雄、相对阵营/座位、手牌数量/上限、治疗/上限、宝石/水晶/容量 |
| team ×2 | 士气、星杯、公共星石 |
| card | 本人手牌、场上牌、状态牌、公开弃牌，以及明确公开的场外五系束缚；牌种、属性集合、命格集合、独有技、区域、效果、持有者/施加者 |
| skill | 当前拥有技能、所属玩家；包括状态牌授予的技能 |
| heroState | 英雄目录中的类型化字段声明，当前为数值、布尔、枚举、牌引用 |
| turn / extraAction | 阶段、路线、攻击次数、已用技能、每项额外行动的类型/属性/来源/顺序 |
| reservation | 仅当前行动者可见的已选牌、目标、技能和预留资源 |
| question | 决策类型、技能、用途、触发时点、来源/目标、伤害类别/数额、命中/防御限制、应战链起点/深度、魔弹方向/参与者 |
| history | 最近32条结构化公开事件，含顺序；不读取呈现快照或隐藏日志 |
| piles | 抽牌队和弃牌堆总数，不含未知牌面 |

候选同样采用类别/数值/实体引用，但不进入Transformer的实体自注意力，避免候选数量引发平方复杂度。候选用牌引用对应card，目标引用对应player，技能引用对应skill；同属性普通刀与独有技刀始终可分别选择。整组弃牌费用以集合表示，目标按位置表示。

## 3. 英雄状态与可见性契约

每个英雄的声明放 `src/heroes/<name>/observation.js`，规则实现仍在同目录。当前运行时拒绝未知英雄或未声明的状态字段。不能在中央编码器不断添加英雄ID分支。

未来字段需在以下结构中选择，新增时扩展声明解释器，而不是修改网络层数或给英雄开专用网络：

| 字段/关系 | 适用实例 | 要求 |
| --- | --- | --- |
| number / boolean / enum | 元素、形态、禁制面、永久解除、罪等 | 数值与上限分开；允许超上限和无上限，不因常规上限裁剪 |
| playerRef / cardRef / entityRef | 格斗固定目标、封印来源、牌上叠牌 | 引用实体，不把ID当连续数值；来源/持有者/受影响者分开 |
| set | 本回合攻击过的人、受法伤的人 | 无顺序；不等同于单个布尔或计数 |
| orderedList | 音符、预言堆、结算步骤、目标序列 | 保留位置，禁止集合池化后丢掉顺序 |
| duration / useScope | 到本人下回合、全局回合限定、仅下一刀 | 明确参照玩家、到期时点、剩余次数，不能只写“本回合” |
| shared state owner | 铸律者/红衣主教互换保留资源 | 英雄替换改变技能集，玩家/牌实例及共享资源保持身份 |

可见范围统一为public、owner和explicit viewers。最后一种用于女仆长、捣蛋萝莉等“只有查看者知道”。只有public/owner在当前18英雄字段解释器中使用；explicit viewers等未来适配需与对应规则一起落地，不在此伪造未实现状态。

盖牌必须将“牌实体存在/位置”与“牌面可见”分离。其他人只看到允许公开的数量、区域和顺序信息；不发内部牌ID、隐藏属性或用于匹配真实牌的稳定指纹。公开来源转盖牌后可记得已展示的内容，但洗混/不可区分移动后只能保留集合或分布知识，不能从引擎真实位置追踪身份。已知集合不等于知道其中每一张的顺序。

## 4. 牌、区域与身份

卡牌是单一真实实体，附加效果仍由牌承载。普通/专属、基础效果/专属牌效果不可混为一类。相同中毒分别编码；圣盾、封印、专属效果的实例及来源关系均保留。

旁置区域还需携带区域类型、承载实体、是否有序、容量、牌面可见范围：精灵祝福可当手牌，结界公开，妖力私有，天平左右是不同容器，预言是专属牌内部的有序牌堆。不能仅靠目前的hand/status两个位置猜测行为，也不能把“盖牌”固定为对持有者可见——需按实际规则声明查看权限。

牌基础属性和当前视为属性必须分开。候选若能选择属性/命格/牌种身份，应显式带上本次解释，例如噬神者的双属性刃、猎巫人的法术视为攻击。合法身份由规则给出，不能让模型自行构造非法牌。

## 5. 决策、顺序与时间

当前保留完整合法候选，不按旧规则AI分数截断。目标A→B与B→A分别枚举；当前训练端已补上。确定性规则AI可以继续使用自己的既有排序，但不能用其排序限制网络可选动作。

将来遇到大量组合时，拆成“技能/模式→牌组→有序目标→可选费用”。每一步必须带已选前缀与可完成的后继限制，允许取消和更换；承诺前不能移动牌或支付真实费用。子步骤属于同一游戏决策时间，不能每选一个目标额外折扣一次回报。无法完成的前缀不得列为合法选项。隐藏承诺和揭示由引擎执行，模型只看该座位当时有权知道的内容。

时点使用明确Timing；同一时点按优先级处理。强制命中仍通过时点2，应战链每次由实际被指定者决策。伤害类别attack/spell独立于行动类别；法术技能也可能造成攻击伤害。还需表达伤害来源、是否降士气、是否可治疗、替代/转移伤害以及原始事件关系。

额外行动可放弃，额外回合与额外行动不同。传教士的动态回合顺序需单独队列，不从物理座次猜测。顺序结算每一步之后检查胜利，达到条件后中止后续效果；未来不引入平局奖励。

## 6. 网络、训练和评测

共享实体Transformer + 候选引用评分 + 参数独立的价值网络。实战仅计算策略。当前无oracle critic、辅助隐藏牌预测或搜索，不共享跨座位私有循环状态。后续若加入记忆，只能更新每个座位自身观测形成的记忆，并在重开时清空。

监督起点使用规则AI的合法选择，价值标签仅终局±1；截断局不能当失败。按整局/seed划分数据，词表只从训练部分拟合。规则候选全分数/排名可以作为同信息来源的辅助输入，但缺失分数不能冒充0分；当前尚未接入这一辅助特征。规则AI既是教师也是可选陪练，不是最终上限。

表示对照必须使用同一观测信息、相同整局切分，不能让旧模型缺少新状态后宣称Transformer更强。至少报告各决策类型准确率、价值误差、未知特征率和运行吞吐。监督指标只说明拟合表现；正式强度用固定阵容、换座位/阵营/先手、固定对手及未调参的种子，并报告区间。多训练seed在正式强化学习对照阶段进行，不为这次接口施工安排大规模重复训练。

检查点保存schema、词表、模型配置、权重、优化器、随机状态和数据切分；规则/教师版本与采集来源也应固定。规则改变后旧胜率不自动有效。不同schema拒绝加载；部分迁移必须是单独明确的工具，不静默兼容。

## 7. 当前完成范围

18英雄持久状态、现有合法决策、事件上下文和实体网络已接入；六包机制审查已完成并形成上述契约。未来英雄的盖牌、角色替换、容器和动态座次等规则仍未实现。同信息的小规模监督对照、精确恢复检查、终局回报策略更新及本次完成审计已完成；本文件不是“所有英雄已经能玩”的声明。


## 按需分步行动（entities-v3）

共享策略网络、结构化实体编码、候选动作评分和独立参数价值网络保持不变。仅当行动候选超过128个时，训练适配器按“行动/技能/模式 → 牌集合 → 有序目标 → 剩余费用和字段”进行条件选择；单一分支自动通过。小集合和响应等其他问题维持完整候选评分，不全面强拆。

每个阶段只保留可完成的合法行动。question.stage 标明阶段，decisionPrefix 实体记录此前选择，候选提供剩余可行组合数量以及可用牌/目标引用。多牌仍整体选择，目标顺序保留；这些摘要不编码全部后续组合之间的关系。最终返回原始完整命令索引，分步期间不修改游戏、不支付费用。这里只优化网络每次评分规模，合法命令仍先完整枚举，不声称解决任意规模的组合生成问题。

采样器、监督数据采集和在线训练共用同一分步适配器。教师先选完整命令，再映射到对应分支，策略可以自行选择任意合法分支。规则AI无需拆分。引擎决策计数仍按完整决策计，训练轨迹记录实际网络子决策；每一步使用相同终局团队胜负，不引入子步骤折扣或中间奖励。

schema 升至 entities-v3，旧v2权重/数据拒绝直接加载，需要重新采集和训练。模型推理只运行策略网络，价值网络仅训练时使用；价值网络当前也只读取合法观测，不包含特权隐藏信息。

本次验证：92项核心规则、5项实体接口检查；144个组合逐个验证教师路径与最终命令一致。6局采集、4步GPU监督训练和6局GPU批量推理贯通；另3局终局奖励训练完成、无截断，执行24次参数更新；仅验证工程接口，不代表模型强度达到线上版本。线上模型保持现有版本。
