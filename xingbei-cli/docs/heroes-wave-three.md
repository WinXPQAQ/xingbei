# 第三批六英雄实施记录

本批实现暗杀者、魔剑士、仲裁者、贤者、祈祷师、英灵人形。继续采用每批6位的流程：规则与基础AI评分同时实现，完成必要验证后部署4174，再由用户试玩反馈。4173原服务、机器学习任务及冻结历史AI不因本批自动更新。

六人坐次仍为红蓝蓝红红蓝，玩家位于0号。新英雄加入共用注册表，网页和终端从同一列表选择；体验服的新六人阵容由服务配置指定，不把引擎原六人默认阵容悄悄替换。精灵射手、灵符师等依赖私有盖牌的新角色不在本批范围。

“无法应战”不等于“强制命中”：圣光及圣盾仍按原规则生效。额外攻击/法术仍允许放弃。使用、明弃、暗弃及效果移除沿用现有实体移动和曝光接口；祈祷赐福是基础牌承载的基础效果，不能另造一份状态实体。

## 共用规则接口

- `Hero.initialize(game, player)`在构造完成、牌与状态容器可用时为每个英雄调用一次；用于初始资源和效果注册。关闭英雄规则时不生成英雄特权。
- `Timing.DRAW_BEFORE`与`Game.drawSteps`提供可决策的摸牌流程。普通技能摸牌、伤害摸牌、购买/合成、无法行动换牌共用该流程；购买/合成显式带`specialAction`，水影据此排除。开局发牌仍由底层`draw`完成，不伪造技能摸牌时点。
- `Game.getEnergyLimit(playerId)`聚合`modifyEnergyLimit`。获得能量、提炼合法性和费用、AI合法动作、网页及终端容量显示均查询此接口，贤者不能只显示4格而实际仍按3处理。
- `src/card-sets.js`统一生成合法牌组。技能可声明`cardCounts`、整组`cardsFilter`以及`targetCountsByCardCount`；同系要求存在共同有效属性，异系要求能为每张牌匹配一个不同的有效属性，兼容未来多属性牌。`chooseCardSet`仍使用选牌后确认，可取消的响应不自动支付。
- `Hero.allowsAction`、`allowsCard`、`canBeAttackTarget`分别约束强制行动、牌的使用范围及目标资格。限制落实到引擎合法性和最终执行校验，不能仅隐藏按钮或只要求AI遵守。启动后重新验证原牌、整组费用、资源和目标；已失效的原选择返回重新选行动，不能用被弃掉的旧牌继续结算。
- `damageSteps`为新的技能伤害创建独立上下文；嵌套法伤不能复用外层攻击上下文。`moraleLoss:false`只约束明确指定的那段伤害/摸牌，进入其触发技能时不继续传播。例如双重回响自身不掉士气，但由它引起的贤者反弹等新伤害仍按各自规则结算。
- 连续伤害逐段`yield* damageSteps`；胜利后共用驱动消费终局请求并关闭整条结算链。黑暗诅咒、魔道法典、法术反弹等对目标先获胜时，不再执行自己的后续伤害，也不会形成平局。

## 旧版依据与边界处理

原版只读来源为`xingbei-1.6.7-source/`，新增实现不修改或重排原目录。以下行号对应本地当前十周年源码，技能文字与实际结算共同核对：

| 角色 | `character/shiZhouNian.js`实现入口 | 技能文字入口 |
| --- | --- | --- |
| 暗杀者 | 508 | 9323 |
| 魔剑士 | 3416 | 9521 |
| 仲裁者 | 2394 | 9446 |
| 贤者 | 5390 | 9648 |
| 祈祷师 | 3809 | 9551 |
| 英灵人形 | 4311 | 9585 |

**零伤害不算承受伤害后。** 旧`noname/library/element/player.js:6790`为伤害事件设置`filterStop`，`num<=0`时发出`damageZero`并结束；因此不会到达`content.js:10937`的`chengShouShangHaiAfter`。新技能虽然绑定共用`DAMAGE_AFTER`，仍明确检查实际伤害：反噬和审判浪潮要求大于0，贤者反弹要求等于1，智慧法典要求大于3。

**形态降低手限会立即爆牌。** 旧`noname/library/index.js:11013`的`_baoPai`监听横置、重置等事件；`player.js:11358`的`qiPai()`按超出手限数量请求强制弃牌并标记`baoPai`；`content.js:9507`在该弃牌未明确免除士气损失时扣除等量士气。当前在潜行、仲裁仪式及符文改造结束等降低手限的节点调用`drawSteps(0)`，仅触发超限处理，不摸牌、不触发水影，也不凭空免除士气损失。

**光辉信仰的弃牌是效果，不是两牌发动门槛。** 旧`shiZhouNian.js:3809`的合法性只检查形态和符文，结算按现有手牌最多弃2；因此0或1张手牌仍可发动，不把不足两张误判为无法使用。

**命中与未命中的响应互斥保留。** 英灵人形的怒火压制与魔纹融合以当前攻击上下文记录已选分支，不能同一次未命中连续触发；符文翻转保持总数3。一次施法/攻击产生的额外行动也仍经过现有回合流程，不能在技能里直接更换当前玩家。

## AI与呈现

应用版本为 **0.8.0**，确定性策略为 **AI 1.8.0-preview.1**，各英雄评分位于`src/heroes/<英雄名>/ai.js`，组合入口为`src/heroes/shared/ai/wave-three/index.js`。新六英雄有独立留牌、行动和响应评分；原12英雄普通决策继续委托`v1.7.0-preview.4`。赐福响应、免士气伤害的治疗判断按实际机制处理，持有者可以是旧英雄。不加载旧神经网络，不启动训练，旧胜率不能套用到本批。

| --- | --- |
| 暗杀者 | 水牌在通用留分上首次+24、重复+8；水影主要用于避免即将发生的爆牌，不随意丢掉圣光或预选行动费用。潜行比较支付后能量加伤、无法应战收益与降低手限成本，摸1牌仅在有安全空间时选择。 |

暗灭和圣光保留原有高价值；上述是通用分数的增量，不是独立优先级列表。卡牌消耗按留分换算成本，圣光/暗灭的高价值不会被新英雄加分覆盖。新英雄通常提炼恰好2颗：魔剑士、贤者不提无用途水晶；暗杀者剩余水晶可贡献潜行加伤，仲裁者/祈祷师/英灵人形有水晶技能。旧12英雄既有无用水晶过滤保留。

本版只做有限的当前行动及明确追加行动推演；没有全局搜索、隐蔽手牌猜测或新的胜率验收。模型对复杂跨回合协作仍是近似，后续以试玩发现的具体问题修正，不能把完整对局通过等同于策略强度。

公开观测仅添加审判、符文、横置形态、动态能量上限等公开字段。手牌组合费用只从当前决策玩家自己的手牌产生；不读取其他玩家牌面或未来牌序。新头像、指示物和祈祷赐福图标复用原项目素材，资源清单保留来源与哈希。
