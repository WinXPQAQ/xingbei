# 六英雄实施记录

按狂战士、风之剑圣、神箭手、封印师、守护天使、神官依次完成独立goal，各建一个本地commit，不push。以用户规则及十周年技能文字为准，旧引擎用于核对时点。六人红蓝蓝红红蓝，0号玩家控制当前验收英雄。基础引擎历史场景显式heroRules=false，避免将没有技能的历史基准误认为新英雄规则；正式网页默认启用已实现技能。

## Goal 1：狂战士（v0.4.0）

实现狂化、血影狂刀、血腥咆哮、撕裂，英雄可选响应与治疗选择共用Session等待。攻击上下文记录六判定时点：attackDeclared(1)、attackDecision/hitCheck/hit(2)、damageBefore(3)、healingBefore(4)、damageActualBefore(5)、damageActual(6)。强制命中仍执行时点2，不消耗圣盾、不请求应战/圣光，后续治疗正常。狂化主动和应战均生效；命中时手牌数量在时点2保存，撕裂在时点3决策并消耗个人宝石。

150张牌逐实体还原uniqueSkills，属性和命格相同可能标签不同；保留3张圣光的治疗术。标签使用英文、中文显示，未实现英雄的标签不自动提供能力。来源：card/xingBei.js完整150行牌表；character/shiZhouNian.js狂战士258—333行及技能文字；noname/library/element/gameEvent.js强制命中；layout/default/layout.css的.card > .range。未改旧项目。

40项Node测试通过；桌面1440×900与触屏390×844共17项英雄浏览器检查通过，控制台/素材错误0。证据artifacts/heroes/berserker/，入口/web/dev.html?scene=hero-berserker。检查包括待提交取消、血腥咆哮、拒绝撕裂不扣费、圣盾保留、治疗及六时点。数值边界、血影狂刀与应战增伤由Node链式测试覆盖；未将这些描述为全部旧版自然技能流程视觉对照。独有技文字直接提取旧range规则，原有布局保持。

## Goal 2：风之剑圣（v0.4.1）

实现风怒追击、圣剑、烈风技、疾风技、剑影。TurnFlow保存额外攻击行动及风系限制，优先消费最后获得的限制行动；玩家可以直接结束回合放弃剩余行动。启动只执行一次，主动攻击逐次计数，应战不计入第三次主动攻击。圣剑在第三次攻击的时点2强制命中；行动结束可以摸0至3张并暗弃同样数量，先完成换牌再判断剩余爆牌。烈风技忽略圣盾并禁止应战，仍允许圣光。水晶费用可以选用宝石代替。

网页、终端与AI共用额外行动队列，网页限制不能使用的手牌并提供结束回合；终端使用end。默认测试0号风之剑圣、1号狂战士，其余角色技能尚未实现。技能来源character/shiZhouNian.js及原版额外行动队列，未修改旧项目。

42项Node测试通过，两视口13项浏览器检查通过，控制台及素材错误0。证据artifacts/heroes/windSwordmaster-final/，入口/web/dev.html?scene=hero-windSwordmaster。覆盖额外行动叠加、风系限制、扣费、放弃；Node另覆盖第三次攻击强制命中、圣盾保留、换牌及烈风技响应限制。没有声称全部原版技能界面已完成视觉对照。

## Goal 3：神箭手（v0.4.2）

实现闪电箭、贯穿射击、闪光陷阱、精准射击、狙击。行动技能由Game验证费用与目标后才进入法术行动；网页、终端、AI共用合法技能描述与结算。费用牌和目标选择都可以取消，目标提交前不扣费。贯穿射击在主动攻击未命中后询问是否明弃法术牌，再造成2点法术伤害，不建立新的法术行动。精准射击支持主动与应战；闪电箭仍允许圣光。

狙击直接补手牌至5，保留directDraw来源，绕过伤害与治疗时点；爆牌仍暗弃并降低士气，再获得可放弃的额外攻击。正式手牌上限不变，隔离场景神箭手上限4测试自狙击爆牌。来源character/shiZhouNian.js1329—1450行及技能文字。

44项Node测试、两视口15项浏览器检查通过，控制台/素材错误0。证据artifacts/heroes/marksman-verified/，入口/web/dev.html?scene=hero-marksman。浏览器覆盖取消、费用、补5暗弃、士气和额外攻击；Node覆盖贯穿响应、闪电箭、精准射击与陷阱。其他英雄尚未实现，技能呈现沿用现有选择组件，未声称全部旧界面视觉对照完成。

## Goal 4：封印师（v0.4.3）

实现法术激荡、五种封印、五系束缚、封印破碎。封印为带对应独有技的基础攻击牌挂载，禁止同名重复，每张牌独立保存来源。共用cardExposed事件保存离手前有效属性：使用、手牌展示、明弃触发；暗弃、covered盖牌标记及状态牌离场不触发。规则事件队列在规则检查点处理，与动画队列无关。

有封印师时登记唯一fivefoldBinding专属实体，初始outside；费用支付后挂到对手，触发后返回outside，可复用；无封印师不生成。优先级中毒3、束缚2、虚弱1。束缚摸牌数2+min(2,场上封印实例数)，若有虚弱再加3，一次选择、同时移除虚弱；可以选择跳过。封印破碎只收入基础效果牌，清除attachment并保留原实体，不收专属牌。来源character/shiZhouNian.js616—1118行及技能文字。

46项Node测试，两视口13项浏览器检查通过，控制台/素材错误0。证据artifacts/heroes/sealer/，入口/web/dev.html?scene=hero-sealer。浏览器验证挂载、标记、法术激荡拒绝和场外牌；Node验证五类展示边界、绑定与虚弱合并、场外复用条件和收取。盖牌仅预留触发排除标记，尚无盖牌玩法。

## Goal 5：守护天使（v0.4.4）

实现风之洁净、天使祝福、天使羁绊、天使之墙、天使之歌、神之庇护。移除接口只接受基础牌，五系束缚不能被天使移除。墙将原攻击实体挂为holyShield；使用墙/圣盾或主动移除基础效果触发羁绊，选择任意角色加1治疗。普通治疗上限2。祝福选择1或2人，分别给2张或各给1张，不足按现有手牌给；给牌不构成公开展示，不触发封印。

新增turnBefore时点，天使之歌在turnStart与中毒前响应；一轮仅出现一次。爆牌结算具有moraleBefore检查点，draw保留cause，神之庇护只抵御己方spell damage引起的士气下降，不改变伤害、摸牌和暗弃。同步/异步均驱动同一规则迭代器，网页暗弃选牌后可以继续等待天使响应。中毒可在治疗时点选择治疗，保留显式poisonHealing供调用者决策。来源character/shiZhouNian.js1120—1328行及技能文字。

## Goal 6：神官（v0.4.5）

实现神圣启示、神圣祈福、水之神力、圣使守护、神圣契约、神圣领域。治疗上限通过技能修正为6，防御治疗每次最多1。祈福明弃两法术牌，水之神力明弃水牌后强制给另一张手牌并各增1治疗；只有最后一张水牌时按原代码跳过给牌，治疗照常。领域的两张费用牌暗弃，不触发封印，支持付1治疗造成2法术伤害或自己+2/队友+1治疗。

契约仅在普通路线首次启动响应，费用可用宝石替水晶；扣除选择的X治疗，目标最高4，超出目标容量的部分按原代码不会获得。普通增疗不会压回已超过上限的治疗。启动导致预选技能费用/选项失效时，保留启动结果及手牌，返回重新选择普通行动，不卡住回合。治疗槽显示实际上限与已有超上限数量；终端同步显示治疗和新增附加效果。AI能提炼取得技能能量、使用合法行动和响应，保留简单决策，不代表策略完整。来源character/shiZhouNian.js4556—4755行及技能文字。

## 圣光响应按钮与天使之墙图标（v0.4.7）

圣光待提交时仅显示“确认”，提示“xxx对你使用xxx，确认使用圣光”。再次点击当前牌或Esc撤回，仍可切换合法响应牌；不响应只在未选牌时显示。攻击/魔弹选目标期间仅保留取消，撤回后才可以不响应。规则结算和选牌不移牌原则保持一致。

检查天使之墙发现其已按attachment.effectId=holyShield显示圣盾图标，不按承载攻击牌的牌面显示。桌面、触屏均复现正常，圣盾素材成功加载，没有复现缺失图标；新增挂载后羁绊选择期间及结算后的实际DOM/图片加载检查，而非仅验证规则状态。本批未修改图标素材、位置或效果规则。
