## 结论

本次最小修复关闭了已发现的普通首次行动 pass 漏洞。未发现阻止该规则修复候选验收的代码问题。强度结论须等待独立核对新评测数据，不能沿用历史胜率。提炼与无法行动刷新保留既有引擎语义，并非本次新增兜底。

`TurnFlow.end()` 先检查行动已经完成，不再调用 `endAction()` 把尚未完成的行动直接收尾。普通回合未行动、正在结算及强制爆牌未处理时不能结束。虚弱规则明确跳过行动阶段、游戏已终结和已完成普通行动后的额外行动，保留各自既有边界。

所有版本注册入口经过 `legalPolicy`，按共享 `legalActions` 过滤历史评分结果；即使所有合法动作负分，也不会选择普通 pass。历史评分器完全漏掉合法候选时，选择确定的合法候选，而不是发明跳过或强制伤害。该回退只保证合法，不保证策略最优。CLI、Web、同步 runner、自动评测及辅助诊断执行入口的 pass 均调用受校验的 `skipExtraActions`。

根行动的非法 pass 被过滤；economy4 `bestAttack` 的零收益停止用于合法额外攻击续行，保留正确。原始 `traceDecision/replayTrace` 仍反映冻结评分器，可能含普通 pass，不能直接当作可执行决策；回归名称和断言已说明这一边界。

## 规则证据与范围

仓库 `src/player.js` 默认手牌上限为 6，当前六英雄未提高该上限。无合法牌或英雄行动时，0–3 张可购买，4–6 张可按现有条件展示弃置并重摸。刷新条件仍包括空余位不超过 2、全部手牌不可用、静态技能标记及合法英雄行动检查；没有放宽成任意刷新。

提炼原本就在 `engine.js` 以 `beginAction(actorId, "special")` 开始、`endAction()` 完成，消耗 1–2 个战绩星石并转成个人能量。独立真实引擎检查确认提炼后 `route=special`、`completed=true`，能够结束回合。README、SOURCES 的 `_tiLian` 记载和既有实现支持该旧行为，但本 checkout 不含所引用的原版源码，不能称重新核验了原版规则书。

用户列举攻击、法术、购买合成强调必须实际行动；本修复不据此新增允许类型。若该列举被明确要求作为穷尽集合，则需要进一步裁定已有提炼和无法行动刷新的地位，不能悄悄将提炼变成免费附属行为。未来提高上限或引入 `canActWithSkills=true` 但当时无技能可用的英雄可能出现未覆盖的无候选状态；当前适配器会报错，不会补 pass。

启动技仅设置 `activationDone`，不会设置 `completed`。独立实际运行神官契约导致预选领域失效的链，确认启动已完成而行动未完成，此时结束回合被拒绝；现有英雄回归也新增这一断言。强制选牌不能用 null 放弃，明确 optional 的请求可以；攻击/魔弹响应、虚弱和额外行动不能与普通必做行动混为一谈。
