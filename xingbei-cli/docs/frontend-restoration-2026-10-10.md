# 对局样式与交互统一记录

日期：2026-10-10。本次修改真实网页版，覆盖当前已支持对局功能；不代表原版全部前端、角色技能或所有设备分支已经还原。

## 首批四人局已实现（历史）

- 背景改为原版 music 网格与渐变；复用本地字体、头像、牌面、星石和治疗槽素材。
- 根据 nova 公式定位对局区、四个相对座位、本人手牌、控制栏与右下战绩。使用原版设备缩放和逻辑视口，移除原先四角布局、插画背景、左上红蓝卡片和常驻日志。
- 玩家显示原版头像裁切、竖排角色名、阵营、手牌数及黄色回合光效。治疗槽读取真实 `healing`；状态与非零能量按原版标记位置显示。头像名称仅用于展示，具体技能尚未实现。
- 方形牌面及系别/命格层、112px间距、最小32px重叠、滚动和折叠文字依据原版实现；单牌与空手牌单独处理。
- 应战、魔弹响应、爆牌使用同一底部手牌组件。目标可取消，非法目标不提交；合成/提炼直接选实际星石。按用户后续要求，合成选择3个、提炼选择1至2个后点击“确认”才结算，已取消原先的选满自动提交。
- 日志通过“记录”打开，可滚动、清空和关闭；重开、整理手牌、牌库/弃牌信息保留。未接入功能不放置伪按钮。
- 独立开发入口支持固定场景、重置、暂停/单步AI及JSON导出。正式入口与开发入口共用渲染和交互模块。重置取消未完成选择、计时器与回合等待。
- 增加字体、治疗槽和 `/review/` 证据路由；无新增生产依赖、构建步骤或第二套规则。原版代码和资源来源见 [来源记录](../SOURCES.md)。

## 复现与证据

从工作区根目录启动新版：

```bash
HOST=0.0.0.0 npm --prefix xingbei-cli run web
```

服务监听 `0.0.0.0:4173`，供外部设备验证。下列地址用于本机访问；从其他设备访问时，将 `127.0.0.1` 替换为服务器实际 IP（例如 `http://服务器IP:4173/`），开发场景及对照页路径保持不变。`0.0.0.0` 是监听地址，不是外部访问地址。

外部连接复查发现此前交互终端启动的进程已退出，端口无监听，本机和 Tailscale IP 均连接失败。现改为用户级 systemd 临时服务 `xingbei-web` 独立运行；确认监听 `0.0.0.0:4173`，服务器本机请求 `http://100.110.150.77:4173/` 与对照页均返回 HTTP 200。尚未代替外部客户端验证完整连接。使用 HTTP，当前未配置 HTTPS；服务管理和重新启动命令见 [README](../README.md)。

- 正常对局：`http://127.0.0.1:4173/`。
- 固定开局：`http://127.0.0.1:4173/web/dev.html?scene=opening`。
- 交互对照：`http://127.0.0.1:4173/review/restoration/2026-10-10/compare.html`。
- [证据目录](../artifacts/frontend/restoration/2026-10-10/)；原版新增截图、DOM、配置、测量在 `original-expanded/`，新版验证产物在 `validated/`。不覆盖9月基准。

场景包括 opening、hand-0/1/4/6、target、unusable、purchase、synthesize、refine、attack、magic、weakness、statuses、overflow、end。`attack` 用显式脚本输入指定蓝一攻击本人，随后真实引擎处理应战链；不会改动正常AI。`magic` 和 `attack` 初始停在AI回合，点击单步进入响应。

开发入口初始暂停AI；单步放行一个AI回合，需要人类应战时等待实际输入。暂停在回合边界生效。正常游戏重开使用新种子；开发工具“重置”重新进入所选固定场景。导出用于排查，未提供状态导入或存档恢复。

原版采集在隔离浏览器里进入教程、选座位、狂战士及默认四人开局。新增特殊状态部分通过**明确标注的运行时准备**得到：手牌数量、星石、markSkill和直接结束；素材及DOM由原版自身生成，未修改源码。它们属于界面依据，不算真实完整游戏流程通过。窄屏原版证据来自同一桌面对局缩放，实际 `touchscreen=false`。

## 同日后续：缓存与操作修正

本批随后增加测试版本标记：`TEST_MODE=1` 时正式入口和开发入口顶部中央显示 `测试 v0.1.1`，版本读取自 `package.json`。普通启动不显示；当前Tailscale外部验证服务启用测试标记。该标记不参与对局缩放、不拦截点击。代码、文档和测试保存为首个本地提交，原项目及截图产物保留在本地。

版本标记在四个既有视口完成浏览器验证：不越出视口、不遮挡顶部重开/牌库按钮、不拦截点击，测试模式可见、普通模式隐藏；无控制台与素材错误，截图保存在 `artifacts/frontend/restoration/2026-10-10/version-label/`。本次浏览器检查使用127.0.0.1；Chromium直接访问Tailscale地址的一次导航超时，服务器本机curl访问该地址正常，不据此声称完成外部客户端验证。

按用户的四项要求修改：

- 图片和字体从 `no-store` 改为 `public, max-age=86400`，由浏览器保存本地缓存；ETag和Last-Modified记录资源版本，携带匹配ETag的请求返回304。HTML、JavaScript和CSS继续使用 `no-store`。素材变动后若需立即更新，使用浏览器强制刷新；当前缓存不是离线游戏功能。
- 共用引擎 `addStones()` 将宝石与水晶合计限制为5个，超额新增部分不进入战绩区。购买及攻击日志记录实际获得数量，不再将未获得的星石记为获得。此规则同时适用于浏览器、CLI和AI。
- 合成选3个、提炼选1至2个（受个人能量剩余容量限制）后，均需点击“确认”才结算。确认按钮始终显示，条件未满足时禁用；选满可以调整或取消，不再自动提交。此确认方式遵从用户要求。
- 整理手牌先攻击牌、后法术牌，各组内部按系别和命格排序，保留所有牌实例。

后续验证：33项Node测试全部通过，覆盖战绩上限、接近上限时购买、满额时主动/异步应战命中以及手牌排序。四视口浏览器记录207项通过检查、64张场景截图和12张重置截图，确认/取消/双击防重复、提炼1个与2个、攻击/法术整理均通过，控制台与素材错误为0。开局56个区域几何对照仍满足不超过1px。

**浏览器脚本整体未通过截图复现验收**：`target-390x844`重置前后有1145个像素颜色不同，其中只有坐标 `(294, 841)` 的1个像素超过既有4/255阈值，最大差14/255；其余11张重置截图满足既有阈值，游戏导出状态一致。没有放宽阈值或隐藏失败。截图前已等待字体、图片解码和两次绘制帧；最终脚本继续收集所有交互结果，再因这项截图差异以失败状态退出。该颜色复现差异仍需后续排查，不能把207项通过检查表述为整个浏览器验收全部通过。前两次采集也在同一竖屏截图检查处中断，记录保留于 `fixes-1/` 与 `fixes-2/`。

## 同日后续：应战选择期间切牌（v0.1.2）

用户取消了新增应战确认步骤的要求，最终按“选择牌 → 选择对手”实现：进入目标选择后仍启用全部合法应战牌，点击另一张牌直接切换，当前选中牌沿用原版适配的上浮20逻辑像素与选中光效；目标点击前不消耗牌，提交使用最新选中的牌。非法应战牌保持禁用，原攻击者不能成为反击目标。再次点当前牌、取消或Esc返回应战选牌；“不使用”放弃应战；切换圣光直接抵消攻击。

选择牌与对手保留在同一会话等待中，重置清理全部选择，不复制引擎规则。新增 `attack-switch` 开发场景，使用真实牌实例准备两张合法地裂斩、一张非法风神斩及一张圣光，单步进入真实应战链。当前测试版本更新为0.1.2，服务已重启。

验证：33项Node测试通过；专项工具 `tools/verify-attack-response.mjs` 在四个既有视口通过69项浏览器检查，涵盖桌面click/窄屏tap、切牌、上浮、非法牌与目标、再点/取消/Esc、目标双击仅弃置一次、圣光、放弃应战及等待期间重置，控制台/素材错误为0。截图及结果在 [应战切牌专项证据](../artifacts/frontend/restoration/2026-10-10/attack-switch-2/results.json)。首轮专项检查错误地按牌名数量判断放弃应战，受命中摸到同名牌影响；已改为检查原牌实例仍在手中，失败记录保留在 `attack-switch/`。本次专项通过不改变上一批竖屏截图颜色复现尚未通过的结论。

## 同日后续：魔弹目标点选（v0.1.3）

原版依据为 `card/xingBei.js` 的 `moDan.selectTarget: 1`、按方向寻找未参与角色的 `filterTarget`。新版发起及传递魔弹均使用玩家高亮点选：先选牌，点唯一合法目标后才使用该牌，不加确认；其他玩家不可点击为目标。传递期间沿用应战切牌组件，当前牌上浮，取消/Esc返回选牌，也可切换圣光或放弃传递。

引擎通过同一传递迭代器供同步CLI与异步浏览器使用，合法目标来自引擎，不在前端复制规则。完整参与本轮后清空记录，再按座次选择最近对手；连坐红一→蓝一→红二→蓝二→红一，新一轮红一再传给蓝一。修正此前浏览器在AI使用魔弹前就询问人类的流程，现每次实际传到人类时才等待其决定，也允许多轮分别响应。`magic` 场景由蓝二发起，确保实际传到人类；新增 `magic-start` 发起及 `magic-linked` 连坐场景，均保持150张实际牌实例守恒。正式对局仍为间位，尚未新增座次设置。

验证：35项Node测试通过，新增同步/异步连坐传递、新一轮目标与实际到达响应测试；四视口魔弹专项69项检查及应战回归69项检查通过，控制台/素材错误为0。覆盖唯一目标、非法玩家、取消/Esc、发起/传递等待重置、双击、传递过程中切圣光和放弃。保存8张魔弹截图；最终结果见 [魔弹目标证据](../artifacts/frontend/restoration/2026-10-10/magic-target-3/results.json) 与 [应战回归](../artifacts/frontend/restoration/2026-10-10/attack-after-magic/results.json)。验证中隐藏正常页面不存在的开发工具栏，实际对局卡牌和玩家仍通过click/tap操作，工具重置/单步通过对应按钮触发。前两次采集分别因读取尚未刷新到界面的日志以及开发工具栏遮住窄屏头像而中断，记录保留，后续改按实际弃牌实例验证顺序并排除工具栏遮挡。

版本号与当前外部验证服务已更新到0.1.3，专项工具为 `tools/verify-magic-target.mjs`。本次未补齐原版魔弹自然流程基准，也未重新宣称全量截图复现通过。
